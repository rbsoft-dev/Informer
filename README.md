# Информер

Трей-приложение для приёма уведомлений по HTTP (JSON) из внешних систем (1С, кассовое ПО,
скрипты, сторонние сервисы), их отображения во всплывающих тостах и хранения истории с
фильтрацией по отправителю. Полностью бесплатно, с открытым исходным кодом (MIT).

Кроссплатформенное (Windows / Linux / macOS), с локализацией интерфейса на несколько языков
и возможностью добавлять новые без пересборки.

---

## Скачать готовую сборку

Не нужно ничего собирать самостоятельно — готовые установщики под все три ОС лежат на

(`.exe` для Windows, `.deb` для Linux, `.pkg` для macOS) и запусти — раздел
[Публикация под Windows / Linux / macOS](#публикация-под-windows--linux--macos) ниже
объясняет установку на каждой ОС подробнее.

Собирать проект из исходников (разделы ниже) нужно только разработчикам, которые хотят
что-то в нём поменять.

## Возможности

- **Приём уведомлений по HTTP** — любая система, способная отправить `POST`-запрос с JSON,
  может стать источником уведомлений (1С, кассовое ПО, скрипты, вебхуки)
- **Один переиспользуемый тост**, а не "башня" из окон — новые уведомления не перебивают то,
  что вы сейчас читаете, если оно пришло не первым. Листание стрелками ◀ ▶, "лампочка" 🔔 для
  перехода к последнему новому, кнопка "Показать полностью" для длинных сообщений (окно
  плавно растёт вверх, не съезжая за край экрана)
- **История уведомлений** — полный список с фильтром по отправителю, ручная отметка
  "прочитано", удаление, индикатор новых сообщений с прокруткой к свежим записям
- **Иконка в трее с бейджем** — количество непрочитанных сообщений отображается прямо на
  иконке (как в Slack/Gmail) и в самом пункте меню "История уведомлений"
- **Настройки** — срок хранения истории, порт сервера, требование API-ключа, анти-спам
  лимит запросов, время показа тоста, политика отображения по типу важности, язык интерфейса
- **Локализация** — переводы хранятся в обычных текстовых `.po`-файлах, список языков
  собирается автоматически по факту того, что лежит на диске; новый язык можно скачать по
  прямой ссылке прямо из окна Настроек, без переустановки программы
- **Окно "О нас"** — информация о разработчике, лицензия, встроенная документация по
  использованию и интеграции
- **Кроссплатформенность** — self-contained сборки под Windows, Linux и macOS (Intel и
  Apple Silicon)

## Стек

- **.NET 6** (net6.0)
- **Avalonia UI 11** — кроссплатформенный интерфейс + системный трей (`TrayIcon`)
- **ASP.NET Core Minimal API (Kestrel)**, встроенный в тот же процесс, что и UI
- **EF Core 6 + SQLite** — провайдер подключается в одном месте (`Program.cs`), поэтому
  замена на SQL Server/PostgreSQL — это правка одной строки `UseSqlite(...)`
- **Karambolo.PO** — чтение переводов из `.po`-файлов (формат gettext)
- **Microsoft.Extensions.Configuration.Ini** — официальный провайдер конфигурации для
  чтения `lang.ini` (названия языков в списке выбора)

## Структура решения

```
Informer.sln
├── Informer.Core   — сущности (Notification, ApiKeyEntity, AppSettingsEntity), DTO, NotificationBus
├── Informer.Data   — InformerDbContext, миграции, design-time factory
├── Informer.Api    — middleware (API key, rate limit), минимальные API эндпоинты
└── Informer.App    — Avalonia UI (трей, тосты, история, настройки, "О нас") + точка входа
                       Program.cs, который поднимает Kestrel и UI-loop в одном процессе,
                       + переводы (Localization/langs/*.po, lang.ini)
```

## Как открыть и собрать в Visual Studio 2022

### Шаг 1 — проверь версию Visual Studio 2022

Нужна любая редакция VS2022 (Community — бесплатная и достаточная). Если ещё не установлена
— скачай с [visualstudio.microsoft.com](https://visualstudio.microsoft.com/ru/downloads/).

Если VS2022 уже стоит — на всякий случай проверь обновления: **Справка → Проверить наличие
обновлений**. Устаревшая версия иногда хуже понимает свежие SDK/NuGet-пакеты.

### Шаг 2 — поставь нужный workload (компонент разработки)

1. Открой **Visual Studio Installer** (ищи в Пуске отдельно от самой VS — это отдельная
   утилита-установщик)
2. Найди свою установку VS2022 → кнопка **"Изменить"**
3. Во вкладке **"Рабочие нагрузки"** найди и поставь галку:
   **".NET desktop development"** ("Разработка классических приложений на .NET")
   — без него VS не сможет собрать проект с `OutputType=WinExe` (тип нашего Informer.App)
4. Расширение **"Avalonia for Visual Studio"** из Marketplace **не обязательно** для сборки
   — оно нужно только если хочешь видеть XAML-превью прямо в редакторе (визуальный конструктор
   для `.axaml`-файлов). Без него всё точно так же соберётся и запустится, просто без
   предпросмотра интерфейса на лету

### Шаг 3 — проверь, что .NET 6 SDK установлен

Открой PowerShell:
```powershell
dotnet --list-sdks
```
В списке должна быть строка с версией `6.0.x`. Если её нет — она обычно ставится
автоматически вместе с workload из Шага 2, но если всё же отсутствует, поставь отдельно:
```powershell
winget install Microsoft.DotNet.SDK.6
```

### Шаг 4 — открой решение

Дважды кликни `Informer.sln`, либо в VS2022: **Файл → Открыть → Проект/решение**.

### Шаг 5 — назначь стартовый проект

Решение состоит из 4 проектов (`Informer.Core`, `Informer.Data`, `Informer.Api`,
`Informer.App`), но запускать нужно именно `Informer.App` — это единственный
исполняемый проект (остальные три — библиотеки, у них нет своей точки входа).

В **Solution Explorer** (обычно справа): найди `Informer.App`, **ПКМ → "Задать в качестве
запускаемого проекта"** (Set as Startup Project). После этого его название станет
**жирным** в списке — это подтверждение, что всё сделано верно.

### Шаг 6 — восстановление NuGet-пакетов

Обычно происходит **само собой** при первой сборке — VS автоматически скачивает все
пакеты, перечисленные в `.csproj`-файлах (Avalonia, EF Core, Karambolo.PO,
Microsoft.Extensions.Configuration.Ini и остальные), если стоит галка "Разрешить
восстановление NuGet-пакетов во время сборки" (включена по умолчанию).

Если сборка ругается на отсутствующие пакеты (или после переключения веток/долгого простоя
проекта) — восстанови вручную:
**ПКМ на решении "Informer" в Solution Explorer → "Восстановить пакеты NuGet"**
(Restore NuGet Packages)

Для восстановления нужен доступ в интернет (пакеты скачиваются с nuget.org) — если сборка
происходит на машине без интернета, нужно заранее настроить локальный NuGet-кэш/зеркало.

### Шаг 7 — собери и запусти

`Ctrl+Shift+B` (Build Solution) — первая сборка может занять больше времени (компиляция
Avalonia-разметки, загрузка пакетов), последующие — быстрее.

`F5` — собрать и сразу запустить (или зелёная кнопка "Play" вверху с названием
`Informer.App`). Приложение появится в системном трее — окна не откроется, это ожидаемо
(трей-приложение по задумке).

### Частые проблемы на этом этапе

- **"Не найден workload".NET desktop development"** — вернись к Шагу 2, проверь, что галка
  реально стоит и применена (после установки VS может попросить перезапуск)
- **Ошибки про недостающие типы/пространства имён сразу после клонирования** — почти всегда
  решается через **Build → Clean Solution**, затем **Build → Rebuild Solution** (полная
  пересборка с нуля, а не инкрементальная)
- **"Restore failed" / таймаут NuGet** — проверь интернет-соединение, либо вручную почисти
  кэш: `dotnet nuget locals all --clear`, затем повтори восстановление пакетов

## Как открыть и собрать в JetBrains Rider

### Шаг 1 — установи Rider

Скачай с [jetbrains.com/rider](https://www.jetbrains.com/rider/) — платный продукт, но
доступен 30-дневный бесплатный пробный период; также бесплатен для некоммерческого
использования при определённых условиях (студенты, opensource-мейнтейнеры — уточняй
актуальные условия на сайте JetBrains).

### Шаг 2 — проверь .NET 6 SDK

```powershell
dotnet --list-sdks
```
Если версии `6.0.x` нет — поставь (Rider сам предложит доустановить нужный SDK при первом
открытии решения, если найдёт несоответствие).

### Шаг 3 — плагин Avalonia (опционально, но рекомендуется)

В отличие от VS2022, для Rider есть полноценный официальный плагин **"Avalonia"** от
JetBrains Marketplace — даёт живой XAML-превью, автодополнение по стилям/ресурсам, шаблоны
файлов. Ставится через **File → Settings → Plugins → Marketplace → поиск "Avalonia"**.

### Шаг 4 — открой решение

**File → Open** → укажи `Informer.sln`. Rider сам распознает структуру решения (все 4
проекта) и запустит восстановление NuGet-пакетов автоматически, без дополнительных действий.

### Шаг 5 — конфигурация запуска

В правом верхнем углу — выпадающий список конфигураций запуска. Rider обычно **сам**
создаёт конфигурацию для каждого исполняемого проекта при открытии решения — выбери в
списке **Informer.App**.

Если конфигурации нет в списке (редкий случай) — создай вручную:
**Run → Edit Configurations → "+" → .NET Project → Project: Informer.App**

### Шаг 6 — собери и запусти

- Сборка: `Ctrl+F9` (или **Build → Build Solution**)
- Запуск с отладкой: `Shift+F10` (или зелёная кнопка "Run" рядом с конфигурацией)
- Запуск без отладки: `Ctrl+F5`

### Частые проблемы

- **Проблемы с NuGet** — ПКМ на решении в панели **Solution Explorer → Restore NuGet
  Packages**, либо `Tools → NuGet → Restore`
- **Странное поведение после смены веток/долгого простоя** — **File → Invalidate Caches...**
  (аналог "почистить кэш и пересобрать" в VS2022), затем перезапуск Rider

## Как открыть и собрать в VS Code

VS Code — не полноценная IDE со встроенной моделью решения, как VS2022/Rider, а
расширяемый текстовый редактор. Работать с ним можно двумя способами: минимально (через
терминал, без специальных расширений) или с расширением, дающим более "IDE-подобный" опыт.

### Способ А — просто через терминал (самый надёжный, без сюрпризов)

1. Установи [VS Code](https://code.visualstudio.com/) и [.NET 6 SDK](https://dotnet.microsoft.com/download/dotnet/6.0)
2. **File → Open Folder** → укажи корневую папку репозитория (там, где `Informer.sln`)
3. Открой встроенный терминал (`` Ctrl+` ``), выполняй команды напрямую:
   ```powershell
   dotnet restore
   dotnet build
   dotnet run --project Informer.App
   ```
   Этого достаточно для полного цикла разработки — редактируешь код в VS Code (базовая
   подсветка синтаксиса C#/XAML работает "из коробки"), собираешь и запускаешь через
   терминал. Просто, предсказуемо, ничего не может "сломаться" из-за капризов расширений.

### Способ Б — с расширением C# Dev Kit (более привычный IDE-опыт)

1. Установи расширение **"C# Dev Kit"** (`ms-dotnettools.csdevkit`) из Marketplace внутри
   VS Code — оно автоматически подтянет и базовое расширение C#, и инструмент установки
   .NET Runtime
2. **Важный нюанс**: C# Dev Kit требует входа в **бесплатный** аккаунт Microsoft (обычная
   учётная запись, не корпоративная подписка) — при первом использовании появится запрос на
   авторизацию, это нормально и ожидаемо, не баг
3. После установки открой папку с `Informer.sln` — в боковой панели появится **Solution
   Explorer** (аналог такого же окна в VS2022), где видна структура всех 4 проектов
4. **ПКМ на `Informer.App` → "Set as Startup Project"**
5. Сборка — `Ctrl+Shift+B`, запуск/отладка — `F5` (расширение автоматически предложит
   создать `launch.json`, соглашайся на предложенный вариант конфигурации)

### Про XAML-превью в VS Code

В отличие от Rider, для VS Code **нет** полноценного официального плагина Avalonia с живым
предпросмотром интерфейса — `.axaml`-файлы редактируются как обычный XML/текст с подсветкой
синтаксиса, без визуального конструктора. Если предпросмотр интерфейса важен в процессе
работы — Rider или VS2022 подойдут для этого лучше.

### Частые проблемы

- **IntelliSense не работает / "не видит" типы** — обычно решается перезапуском OmniSharp/C#
  Dev Kit сервера: `Ctrl+Shift+P` → "Restart Language Server" (или просто перезапуск самого
  VS Code)
- **`dotnet restore` не находит пакеты** — та же причина, что и в VS2022/Rider (нет
  интернета, либо повреждённый кэш): `dotnet nuget locals all --clear`, затем повтори



Открой **Tools → NuGet Package Manager → Package Manager Console**, выбери
**Default project: Informer.Data**, затем:

```powershell
Add-Migration InitialCreate -Project Informer.Data -StartupProject Informer.App
Update-Database -Project Informer.Data -StartupProject Informer.App
```

При запуске `Program.cs` вызывает `db.Database.Migrate()` автоматически, так что после
`Update-Database` один раз (для генерации файла миграции) на других машинах достаточно
просто запустить exe — база создастся/обновится сама.

Дальнейшие миграции при изменении сущностей — та же команда `Add-Migration <Имя>` +
`Update-Database`.

## Запуск

`F5` в VS2022. Приложение появится в системном трее. Правый клик по иконке:
**История уведомлений**, **Настройки**, **О нас**, **Выход**.

При первом запуске:
- Язык интерфейса определяется автоматически по языку операционной системы (если
  подходящий `.po`-файл установлен — иначе используется первый доступный)
- Порт сервера — **`4399`** по умолчанию (настраивается в Настройках, требует перезапуска
  приложения при изменении)
- Kestrel слушает `0.0.0.0` (все сетевые интерфейсы) — см. раздел [Безопасность](#безопасность)

## Публикация под Windows / Linux / macOS

Из `Informer.App`:

```powershell
# Windows (x64)
dotnet publish -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true

# Linux (x64)
dotnet publish -c Release -r linux-x64 --self-contained true -p:PublishSingleFile=true

# macOS Intel
dotnet publish -c Release -r osx-x64 --self-contained true -p:PublishSingleFile=true

# macOS Apple Silicon (M1/M2/M3)
dotnet publish -c Release -r osx-arm64 --self-contained true -p:PublishSingleFile=true
```

Результат — в `Informer.App\bin\Release\net6.0\<rid>\publish\`.

### Запуск на Linux

```bash
chmod +x Informer
./Informer
```

### Запуск на macOS

```bash
chmod +x Informer
xattr -d com.apple.quarantine ./Informer
./Informer
```
(`xattr` снимает карантинную метку Gatekeeper для неподписанных приложений — без этого
macOS откажется запускать файл через двойной клик или консоль до явного разрешения в
Системных настройках)

## Сборка установщиков

Помимо "голой" публикации (`dotnet publish`, см. выше), в репозитории есть готовые скрипты
для сборки полноценных установщиков под каждую ОС — с ярлыками, деинсталлятором,
регистрацией в системе и т.д.

### Структура

```
installers/
├── for-windows/    — Informer.iss (скрипт Inno Setup)
├── for-linux/      — deb-template/ (структура .deb) + build-deb.sh
├── for-macos-intel/ и for-macos-m/  — app-template/ (Info.plist) + build-pkg.sh
                       (Intel и Apple Silicon — используют один и тот же build-pkg.sh,
                       разница только в том, какую публикацию ему передать: osx-x64 или
                       osx-arm64)

dist/               — сюда попадают уже ГОТОВЫЕ файлы установщиков после локальной сборки:
├── windows/Informer-Setup-1.0.0.exe
├── linux/informer_1.0.0_amd64.deb
└── macos/Informer.pkg
```

`installers/` — это исходники/скрипты для **самостоятельной сборки** установщика из
исходного кода. `dist/` — результат этой сборки на твоей машине, **в `.gitignore`**, в
самом репозитории не хранится (чтобы не раздувать историю Git закоммиченными бинарниками
на каждый релиз).

**Готовые установщики для конечных пользователей публикуются через GitHub Releases** —
см. раздел [Скачать готовую сборку](#скачать-готовую-сборку) ниже. Как именно опубликовать
новую версию (загрузка файлов, создание релиза) — описано в
[Wiki проекта](https://github.com/rbsoft-dev/Informer/wiki), страница
**"Как делать релизы проектов"**.

### Windows — Inno Setup

Установи [Inno Setup](https://jrsoftware.org/isdl.php) (6.x или новее), открой
`installers/for-windows/Informer.iss`, **Build → Compile** (`Ctrl+F9`). Перед сборкой нужна
свежая публикация (`dotnet publish -r win-x64 ...`, см. выше) — скрипт берёт файлы оттуда.

Ставит **без прав администратора** (в `%LocalAppData%\Programs\Informer` — не в
`Program Files`, т.к. приложение пишет `informer.db`/`crash.log` рядом с exe, а
`Program Files` недоступен для записи обычному пользователю).

### Linux — `.deb`-пакет

```bash
cd installers/for-linux
chmod +x build-deb.sh
./build-deb.sh /путь/до/publish
```

Перед сборкой проверь актуальное имя пакета `libicu` на целевом дистрибутиве
(`apt-cache search libicu`) и поправь строку `Depends:` в `deb-template/DEBIAN/control`,

Устанавливать **строго** через `apt install ./informer_1.0.0_amd64.deb` (не `dpkg -i`) —

### macOS — `.pkg`

Пакет **не подписан** сертификатом Apple Developer ($99/год, которого у проекта нет) —

Конфиденциальность и безопасность → «Открыть в любом случае»**.



Все настройки хранятся в одной строке таблицы `AppSettings` (SQLite) и применяются **сразу**
после сохранения — за одним исключением:

| Настройка | Применяется | Примечание |
|---|---|---|
| Язык интерфейса | Мгновенно | Не требует кнопки "Сохранить" |
| Срок хранения истории | После "Сохранить" | Фоновая служба чистит записи старше N дней |
| Порт сервера | **После перезапуска приложения** | Kestrel не может перепривязать порт "на лету" |
| Требовать API-ключ | После "Сохранить" | Защищает только `/api/notify` |
| Анти-спам (запросов/за сколько секунд) | После "Сохранить" | Считается по IP-адресу |
| Время показа тоста | После "Сохранить" | В секундах, до автозакрытия |
| Политика отображения (Обычные/Предупреждения/Ошибки) | После "Сохранить" | Управляет только всплытием тостов — в истории видно всегда |
| API-ключи | Мгновенно | Создание/отзыв/удаление применяются сразу |

## Локализация

Переводы хранятся как обычные текстовые `.po`-файлы (формат gettext) в
`Informer.App/Localization/langs/`. Список языков в Настройках строится **автоматически** —
сканированием этой папки, а не жёстко заданным списком в коде.

### Как добавить новый язык

1. Скопируй `en.po`, переименуй в код языка (`de.po`, `es.po`, ...) — используй **настоящий**
   код ISO 639-1 (`de`, не `ger`; `zh`, не `ch`) — от этого зависит и автоопределение языка
   системы, и резервное название языка
2. Переведи строки `msgstr "..."` — удобно через [Poedit](https://poedit.net) (бесплатный
   редактор `.po`, не требует знания кода) или любым текстовым редактором **в кодировке UTF-8**
3. (Опционально) добавь явное название в `Informer.App/Localization/langs/lang.ini`:
   ```ini
   de = Deutsch
   ```
   Без этой строки название определится автоматически через встроенную базу языков .NET —
   явное указание нужно только для нестандартных кодов или чтобы точно контролировать
   написание (заглавные буквы и т.д.)

### Скачивание языкового пакета без пересборки

В Настройках, в карточке "Язык интерфейса" есть поле для прямой ссылки на `.po`-файл — после
скачивания язык сразу появляется в списке и применяется, без переустановки программы.

### Уже переведённые языки

`ru` (русский), `en` (English), `fr` (Français), `zh` (中文, упрощённый).

## API — формат входящего запроса

```
POST http://<адрес>:4399/api/notify
Content-Type: application/json
X-Api-Key: <ключ, если включено требование ключа в настройках>

{
  "header": "1C:Session:MainBase:ivanov",
  "description": "Новый документ проведён",
  "type": "info",
  "ResponseBody": {
    "any": "произвольная структура"
  }
}
```

- `header` — отображается как отправитель, используется для фильтрации в истории; не
  участвует в авторизации
- `description` — текст сообщения
- `type` — необязательное поле: `info` (по умолчанию), `warning` или `error` — влияет на
  цвет рамки тоста и на то, показывать ли тост вообще (согласно "Политике отображения" в
  Настройках); в истории видно всегда, независимо от политики
- `ResponseBody` — произвольная JSON-структура, сохраняется как есть

Авторизация — только через заголовок `X-Api-Key`, сверяемый с активными ключами из
`Настройки → API-ключи`. Обязателен, только если в Настройках включено "Требовать API-ключ".

### Быстрый тест через curl

```bash
curl -X POST http://127.0.0.1:4399/api/notify \
  -H "Content-Type: application/json" \
  -H "X-Api-Key: <ключ_из_окна_настроек>" \
  -d '{"header":"TestSender","description":"Привет из curl","type":"info","ResponseBody":{"x":1}}'
```

## Прочие эндпоинты

Используются самим UI, но доступны и извне для отладки/интеграций. **Не защищены
API-ключом** — см. [Безопасность](#безопасность).

- `GET    /api/history?sender=...&fromUtc=...&toUtc=...&page=1&pageSize=100`
- `GET    /api/history/senders`
- `POST   /api/history/{id}/read`
- `GET    /api/settings`
- `PUT    /api/settings`
- `GET    /api/apikeys`
- `POST   /api/apikeys`
- `DELETE /api/apikeys/{id}`

## Безопасность

- По умолчанию Kestrel слушает `0.0.0.0` (все сетевые интерфейсы), не только `127.0.0.1` —
  это позволяет обращаться к API с других устройств в той же локальной сети
- **`/api/notify`** — защищён API-ключом (если включено в Настройках) и лимитом частоты
  запросов по IP
- **`/api/history` и `/api/settings` — без какой-либо авторизации.** Открыв `0.0.0.0` в
  недоверенной сети, любой в этой сети сможет прочитать историю и изменить настройки
  (включая создание/отзыв API-ключей) без пароля. Подходит для домашней/офисной доверенной
  сети; не делайте так в публичной или незнакомой сети
- Изменить адрес привязки можно через `appsettings.json` → `Kestrel:BindAddress`
  (`"127.0.0.1"` — только локально, `"0.0.0.0"` — вся сеть)

## Диагностика проблем

- **`crash.log`** (рядом с exe) — журнал необработанных исключений. Пишется автоматически
  при старте (`AppDomain.UnhandledException`, `TaskScheduler.UnobservedTaskException`) и
  оборачивает потенциально опасные обработчики событий (показ тоста, окно "О нас" и т.д.),
  чтобы сбой в одном месте не "подвешивал" всё приложение молча
- Если приложение не запускается на Linux/macOS — проверь права на исполнение
  (`chmod +x Informer`) и, для macOS, снятие карантинной метки (`xattr -d
  com.apple.quarantine`)
- Если кириллица/другой не-ASCII текст отображается как "�" — проверь кодировку файла
  (`.po`, `lang.ini`) — должна быть **UTF-8**, не "ANSI"
